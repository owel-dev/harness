# harness

Claude Code와 Codex가 함께 읽는 공통 작업 지침입니다. 에이전트가 스스로 해도 되는 일, 먼저 물어봐야 하는 일, 끝낸 뒤 어떻게 보고해야 하는지를 정합니다.

A shared instruction set for AI coding agents such as Claude Code and Codex. It defines what an agent may do on its own, what it must ask about first, and how it reports finished work.

## 왜 만들었나

에이전트에게 작업을 맡기면 일은 빨라지지만, 사람이라면 하지 않을 행동을 조용히 하는 경우가 생깁니다. 코드를 읽고 판단한 것을 검증했다고 보고하거나, 유료 API를 호출하는 테스트를 묻지 않고 실행하거나, 커밋 메시지에 변경 이유를 남기지 않는 식입니다. 이 저장소는 그런 행동을 하나씩 규칙으로 막으면서 2026년 7월부터 실제 작업에 써 온 기록입니다.

규칙 본문은 [AGENTS.md](AGENTS.md)에 있습니다. 이 문서는 각 규칙이 왜 생겼고 어떤 판단으로 지금 모양이 되었는지를 설명합니다.

## 규칙이 막는 것

| 규칙 | 막으려는 상황 |
|---|---|
| 답변 규칙 | 답변이 영어로 나오거나, 코드와 식별자, 기술 용어까지 한글로 번역되는 것 |
| 문자 사용 규칙 | 가운뎃점, 화살표, 긴 하이픈처럼 AI가 쓴 글에서 흔히 보이는 문자가 답변과 커밋 메시지, 주석에 섞이는 것 |
| 커밋 규칙 | 여러 작업이 한 커밋에 섞이거나, 이유 없는 커밋 메시지가 남거나, 이번 작업과 무관한 변경과 비밀 정보가 커밋에 들어가는 것 |
| 과금 규칙 | 유료 LLM API, 클라우드 리소스, 메일 발송, 결제 API처럼 비용이 생기는 호출을 묻지 않고 실행하는 것. 그런 호출이 들어 있는 테스트를 돌리는 것도 포함합니다 |
| 되돌리기 어려운 작업 규칙 | force push, hard reset, 브랜치 삭제, 대량 삭제를 요청 없이 실행하는 것 |
| 작업 설명 규칙 | 코드를 읽고 판단한 것을 검증으로 포장하는 것. 실제로 실행한 명령과 그 결과만 검증으로 봅니다 |

## 설계 판단

- 규칙은 한 파일에만 둡니다. Codex는 AGENTS.md를 직접 읽고, Claude Code는 `@AGENTS.md` 한 줄만 적힌 CLAUDE.md를 거쳐 같은 내용을 읽습니다. 규칙 파일에 제목과 소개 문단을 두지 않는 것도 같은 이유입니다. 서버의 전역 CLAUDE.md에 본문을 그대로 복사해 쓰기 때문에, 규칙 본문만 있어야 어디에 붙여도 맞습니다.
- 기계적으로 판별할 수 없는 것은 지침으로 둡니다. 과금 여부는 명령 문자열만으로 알 수 없어서 hook이 아니라 지침에 적었습니다. 되돌리기 어려운 작업도 도구가 각자 제공하는 기본 가드레일에 기대지 않고, 두 도구가 같이 읽는 지침에 적었습니다.
- 자율성을 주는 만큼 경계를 긋습니다. 처음에는 커밋도 요청받았을 때만 했습니다. 작업 단위가 끝나면 묻지 않고 커밋하도록 바꾸면서, push와 되돌리기 어려운 작업은 요청받았을 때만 하도록 함께 묶었습니다.
- 도구의 기본 동작을 알고 덮어씁니다. Claude Code는 기본 브랜치에 있으면 브랜치를 먼저 만들도록 안내받습니다. 이 기본값이 자동 커밋과 엇갈리지 않도록, 현재 브랜치에 바로 커밋하고 새 브랜치는 요청받았을 때만 만든다고 적었습니다.
- 규칙이 기대는 말은 정의합니다. 여러 규칙이 "작업 단위"라는 말에 기대고 있어서, 요청받은 기능이나 수정 하나를 구현하고 검증까지 마친 묶음이라고 정의했습니다. git 태그와 혼동되는 "태그" 대신 Conventional Commits 용어인 "타입"을 쓰는 것처럼, 용어도 맞춥니다.

## 시도했다가 뺀 것

규칙은 늘리기만 하지 않았습니다. 효과가 없거나 다른 규칙을 해칠 수 있는 것은 뺐습니다.

- 문체 규칙. 결론을 먼저 말하고, 명사형 종결과 번역투를 피하고, 헤더와 굵은 글씨를 아끼라는 규칙을 두었다가 뺐습니다. 실제 문체가 나아지는지 체감할 수 없었습니다.
- "절대"라는 표현. 문자 사용 규칙에 "절대 쓰지 않습니다"라고 적었다가 "절대"를 뺐습니다. 그 정도로 중요한 규칙이 아닌데 강조하면, 다른 규칙이 상대적으로 덜 지켜질 수 있다고 봤습니다.
- 보안 검사 hook. git commit 전에 lockfile 기준으로 의존성 취약점을 검사하고, git push 전에 gitleaks로 비밀 정보를 검사하는 PreToolUse hook 스크립트를 만들었습니다. 에이전트가 실행하는 명령에만 걸리고 사람이 직접 실행하는 git 명령에는 걸리지 않는다는 한계를 처음부터 적어 두었고, 실제 설정에 등록하지 않은 채 뺐습니다.
- 작업 문서 규칙. 작업 단위가 3개 이상인 작업에 SPEC.md, PLAN.md, PROGRESS.md를 두고, 세션을 시작할 때 PROGRESS.md부터 읽게 하는 규칙입니다. 생성 기준을 "여러 세션에 걸치는 작업"에서 "작업 단위 3개 이상으로 예상되는 작업"으로 바꾸는 등 다듬은 뒤 뺐습니다. 전자는 작업을 시작하는 시점에 판단할 수 없는 기준이었습니다.

## 사용 방법

프로젝트 단위로 쓰려면 AGENTS.md를 저장소 루트에 두고, CLAUDE.md에 다음 한 줄만 적습니다.

```
@AGENTS.md
```

모든 프로젝트에 적용하려면 AGENTS.md 본문을 전역 CLAUDE.md에 그대로 복사합니다.

## 변경 이력

규칙을 왜 바꿨는지는 커밋 메시지에 있습니다. 규칙을 고치는 작업도 이 규칙을 읽는 에이전트와 함께 했기 때문에, 이 저장소의 git log는 커밋 규칙이 실제로 어떻게 작동하는지 보여주는 예이기도 합니다.
